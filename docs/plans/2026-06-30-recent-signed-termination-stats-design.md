# 近两月新签店铺解约统计分类页需求文档

## 1. 需求背景

现有 `数据统计` 页面里的“运营解约数据明细”，统计口径是：

```text
选择某个月份后，统计该月份内解约的所有店铺；
不限制这些店铺是哪个月份签约的。
```

现在需要新增一个独立分类页，用于观察“近期新签店铺”的解约情况。这个页面不再统计所有历史签约店铺，而是只统计“统计月份本月 + 上一个月”签约、并且在统计月份发生解约的店铺。

## 2. 页面目标

新增一个分类页，按运营维度统计每个月的新签店铺解约数量，帮助判断近期新签店铺在刚签约后的解约情况。

页面核心回答的问题是：

- 6 月每个运营有多少家“5 月或 6 月签约、并在 6 月解约”的店铺？
- 7 月每个运营有多少家“6 月或 7 月签约、并在 7 月解约”的店铺？
- 以此类推，每个月只看该月和上月签约的店铺在该月的解约数量。

## 3. 页面名称与入口

建议新增侧边栏分类：

- 页面名称：`新签解约统计`
- 页面路径建议：`/termination/recent-signed-stats`

位置建议：

- 放在现有 `美团解约明细`、`饿了么解约明细` 附近，或放在 `数据统计` 下方。

> 入口名称和具体排序可在实现前再确认，不影响统计口径。

## 4. 核心统计口径

### 4.1 统计月份

用户选择一个自然月作为统计月份，例如：

- `2026-06`
- `2026-07`

统计月份决定两件事：

- 解约时间范围
- 允许纳入统计的签约时间范围

### 4.2 解约时间范围

只统计 `terminationDate` 落在统计月份内的店铺。

例如统计 `2026-06`：

```text
terminationDate >= 2026-06-01 00:00:00
terminationDate <  2026-07-01 00:00:00
```

### 4.3 签约时间范围

只统计 `contractSignedDate` 落在“统计月份本月 + 上一个月”内的店铺。

例如统计 `2026-06`：

```text
contractSignedDate >= 2026-05-01 00:00:00
contractSignedDate <  2026-07-01 00:00:00
```

例如统计 `2026-07`：

```text
contractSignedDate >= 2026-06-01 00:00:00
contractSignedDate <  2026-08-01 00:00:00
```

### 4.4 店铺状态范围

默认只统计：

```text
shopStatus = 已解约
terminationDate 有值
contractSignedDate 有值
```

不统计：

- `正常`
- `新店`
- `无效店铺`
- 没有解约日期的店铺
- 没有合同签订日期的店铺

### 4.5 运营归属

按店铺当前 `operatorName` 分组统计。

如果 `operatorName` 为空，统一归为：

```text
未分配
```

## 5. 与现有统计的区别

| 项目 | 现有运营解约统计 | 新增新签解约统计 |
|---|---|---|
| 统计对象 | 统计月份内所有已解约店铺 | 统计月份内已解约，且本月或上月签约的店铺 |
| 签约月份限制 | 不限制 | 只看统计月和上月 |
| 解约日期 | 必须落在统计月份 | 必须落在统计月份 |
| 分组维度 | 运营 | 运营 |
| 主要用途 | 看整体解约情况 | 看近期新签店铺质量和早期流失情况 |

## 6. 示例说明

### 6.1 统计 2026 年 6 月

纳入统计的店铺必须同时满足：

```text
1. 店铺状态为 已解约
2. 解约日期在 2026-06-01 到 2026-06-30
3. 合同签订日期在 2026-05-01 到 2026-06-30
```

以下店铺会被统计：

| 合同签订日期 | 解约日期 | 是否统计 | 原因 |
|---|---|---|---|
| 2026-05-10 | 2026-06-08 | 是 | 5 月签约，6 月解约 |
| 2026-06-03 | 2026-06-20 | 是 | 6 月签约，6 月解约 |
| 2026-04-28 | 2026-06-12 | 否 | 4 月签约，不属于 5 月或 6 月 |
| 2026-05-15 | 2026-07-01 | 否 | 解约发生在 7 月，不属于 6 月 |

### 6.2 统计 2026 年 7 月

纳入统计的店铺必须同时满足：

```text
1. 店铺状态为 已解约
2. 解约日期在 2026-07-01 到 2026-07-31
3. 合同签订日期在 2026-06-01 到 2026-07-31
```

## 7. 页面功能

### 7.1 月份选择

页面顶部提供月份选择器：

- 默认月份建议为当前月
- 用户可切换历史月份
- 切换月份后重新加载统计数据

### 7.2 汇总卡片

建议展示：

- 当前统计月份
- 签约月份范围，例如 `2026-05 ~ 2026-06`
- 两个月店铺总数范围，例如统计 `2026-06` 时为 `2026-05 ~ 2026-06`
- 新签解约总数
- 两个月店铺总数
- 涉及运营人数

### 7.3 运营统计表

按运营展示统计结果：

| 字段 | 说明 |
|---|---|
| 月份 | 当前统计月份 |
| 签约月份范围 | 上月 + 本月 |
| 运营人员 | `operatorName`，为空时显示 `未分配` |
| 解约数量 | 满足本口径的店铺数 |
| 两个月店铺总数 | 统计月本月及上一个月签约的店铺总数 |

默认排序：

```text
解约数量从高到低；
数量相同按两个月店铺总数从高到低；
仍相同按运营姓名升序。
```

### 7.4 店铺明细表

建议在运营统计表下方展示明细，方便核对数量来源。

明细字段建议：

| 字段 | 来源 |
|---|---|
| 店铺名 | `shopName` |
| 商家 ID | `merchantId` |
| 外卖平台 | `deliveryPlatform` |
| 负责运营 | `operatorName` |
| 合同签订日期 | `contractSignedDate` |
| 解约日期 | `terminationDate` |
| 运营天数 | `terminationCooperationDays` |

明细支持：

- 按运营筛选
- 按平台筛选
- 按店铺名或商家 ID 搜索

> 筛选能力属于页面体验增强；第一版也可以先完成月份统计 + 明细展示。

### 7.5 图表展示

建议展示一个柱状图：

```text
X 轴：运营人员
Y 轴：新签解约店铺数
```

图表数据与运营统计表保持一致。

## 8. 数据来源

主数据集合：

- `shops`

关键字段：

| 字段 | 用途 |
|---|---|
| `shopStatus` | 判断是否已解约 |
| `terminationDate` | 判断是否在统计月份解约 |
| `contractSignedDate` | 判断是否属于统计月或上月签约 |
| `operatorName` | 按运营分组 |
| `shopName` | 明细展示 |
| `merchantId` | 明细展示和核对 |
| `deliveryPlatform` | 平台展示和筛选 |
| `terminationCooperationDays` | 明细展示 |

## 9. API 设计建议

建议新增接口：

```text
GET /api/termination/recent-signed-stats?month=YYYY-MM
```

返回结构建议：

```ts
type RecentSignedTerminationStatsResponse = {
  month: string;
  signedMonthRange: {
    startMonth: string;
    endMonth: string;
    startDate: string;
    endDate: string;
  };
  twoMonthSignedRange: {
    startMonth: string;
    endMonth: string;
    startDate: string;
    endDate: string;
  };
  totalTerminatedCount: number;
  twoMonthSignedShopCount: number;
  operatorCount: number;
  operatorStats: Array<{
    operatorName: string;
    count: number;
    twoMonthSignedShopCount: number;
  }>;
  shops: Array<{
    id: string;
    shopName: string;
    merchantId: string;
    deliveryPlatform: string;
    operatorName: string;
    contractSignedDate: string;
    terminationDate: string;
    terminationCooperationDays: number | null;
  }>;
};
```

## 10. 查询逻辑建议

选择月份 `month` 后，后端计算：

```text
terminationStart = 统计月 1 日 00:00:00
terminationEnd   = 下个月 1 日 00:00:00

signedStart = 上个月 1 日 00:00:00
signedEnd   = 下个月 1 日 00:00:00

twoMonthSignedStart = 上个月 1 日 00:00:00
twoMonthSignedEnd   = 下个月 1 日 00:00:00
```

Mongo 查询条件建议先按两个月签约范围拉取候选店铺：

```ts
{
  contractSignedDate: { $gte: twoMonthSignedStart, $lt: twoMonthSignedEnd },
}
```

然后在业务层分别计算：

- 新签解约数量：`contractSignedDate` 在上月 + 本月，且 `terminationDate` 在统计月，且 `shopStatus = 已解约`
- 两个月店铺总数：`contractSignedDate` 在统计月本月及上一个月
- 最后按 `operatorName` 聚合统计。

## 11. 验收标准

- 用户进入新增分类页后，可以看到一个独立的“新签解约统计”页面。
- 页面默认展示当前月份的数据。
- 用户切换到 `2026-06` 时，只统计 `2026-05` 和 `2026-06` 签约、且 `2026-06` 解约的店铺。
- 用户切换到 `2026-07` 时，只统计 `2026-06` 和 `2026-07` 签约、且 `2026-07` 解约的店铺。
- 页面按运营展示解约数量。
- 页面按运营展示统计月本月及上一个月签约的店铺总数。
- 运营统计数量可以通过下方店铺明细逐条核对。
- 不把更早月份签约但在统计月份解约的店铺计入新页面。
- 现有 `数据统计` 页面里的全量运营解约统计不受影响。

## 12. 待确认事项

以下事项不影响第一版口径，但实现前建议确认：

- 页面入口名称是否确定为 `新签解约统计`。
- 新页面是否需要同时展示“现有全量解约数”和“新签解约数”的对比。
- 明细表是否需要导出 Excel。
- 平台筛选是否第一版就需要，还是先只做双平台合并统计。
- “签约日期”是否固定使用 `contractSignedDate`，而不是 `entryDate`。
